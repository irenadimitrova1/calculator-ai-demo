## Agent Brief

**Category:** bug
**Summary:** After error state, digit/decimal input should clear the session and start fresh (macOS/iOS recovery semantics)

**Current behavior:**
When the calculation session enters **error state** (e.g. divide by zero), the active number shows `Error` and all keypad/keyboard input except **AC** and **C** is ignored. Pressing a digit leaves the display on `Error`. This matches the written v1 spec but diverges from macOS/iOS Calculator, where pressing a digit after `Error` starts a new entry from that digit.

**Desired behavior:**
After **error state**, any input that would normally start a fresh calculation entry should behave like **All Clear** followed by that input — same recovery pattern as pressing a digit after a finished **result**. Specifically:

- **Digit** or **decimal** — reset session (memory preserved), then append to the active number as a new entry
- **Operator** — reset session, then begin a new calculation with that operator (same as digit-after-result chaining semantics)
- **Sign toggle** — reset session, then apply sign toggle to empty active number
- **Equals**, **memory keys** — unchanged blocking rules unless product says otherwise; at minimum digit/decimal/operator recovery is required
- **AC** and **C** — unchanged (both still clear from error)

Update domain docs (`CONTEXT.md` **Error state** glossary and v1 feature spec error bullet) to match macOS/iOS recovery instead of "blocked until AC/C".

**Key interfaces:**
- `CalculationSessionState` with `phase: 'error'`
- `transition()` reducer — error-phase branch currently returns `state` unchanged for non-clear actions; should route recoverable inputs through clear-then-apply
- Post-result digit entry path — reuse the same "fresh entry after terminal state" semantics as `phase: 'result'`

**Acceptance criteria:**
- [ ] After `5 ÷ 0 =`, pressing `1` shows active number `1`, phase `entry`, expression line empty (memory unchanged if set)
- [ ] After error, pressing `.` starts `0.` on a cleared session
- [ ] After error, pressing `+` starts a new calculation with that operator (same as digit-after-result operator behavior)
- [ ] AC and C from error still fully clear the session (existing tests pass)
- [ ] Table-driven session tests updated: replace "error blocks digit input" with recovery scenarios; add decimal and operator recovery cases
- [ ] `CONTEXT.md` and v1 spec error behavior text updated to describe macOS/iOS digit recovery

**Out of scope:**
- Scientific mode / PEMDAS evaluation (#35, v2)
- Changing when error state is entered (divide-by-zero rules stay the same)
- Keyboard handler changes beyond what the session module already supports for digit/decimal/operator dispatch
